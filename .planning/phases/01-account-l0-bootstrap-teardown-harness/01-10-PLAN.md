<objective>
Wire the CI path end to end and close the phase: two Terraform workflows through the OIDC roles, a
scheduled sweep that catches the forgotten session, and the deliberately awkward decommission path
that is the only way the immortal layer can ever be destroyed.

Purpose: the OIDC roles created in plan 01-07 are unexercised until a real workflow assumes them,
and the failure mode for a mis-scoped trust policy only appears at that first run. Equally, the
scoping claim is only proven by a run that is supposed to fail: a workflow that successfully assumes
the apply role proves the role works, not that it is bounded. And the scheduled sweep exists for the
single most expensive mistake this project makes available — a session spun up and never torn
down — which by definition nobody is present to notice.

Output: a green plan run on a pull request, a green apply run on the main branch, a red run from a
branch that should not be trusted, a cron sweep, and a decommission path that cannot be triggered by
accident.
</objective>

  <action>
    Write `scripts/empty-versioned-bucket.sh` from the body in RESEARCH Part B: loop listing object
    versions and delete markers in batches, delete them in bulk, and repeat until nothing remains.
    A versioned bucket cannot be deleted while it holds any version or any delete marker, and the
    force-destroy argument must NOT be set on a state bucket — with it set, a stray destroy would
    silently consume every generation of state history. Emptying explicitly is the safe form. Print
    the count removed per batch so a long run shows progress rather than appearing hung.

    Add `make nuke-bootstrap` to the Makefile implementing the five steps in order, because all three
    of F-10's problems must be solved and they interlock:

    1. **Confirmation.** Print what will be destroyed and require the operator to type a confirmation
       string that includes the live account ID read from the caller-identity call, so the string
       cannot be copied from documentation and cannot be typed by muscle memory against the wrong
       account. Any mismatch aborts.
    2. **Refuse while other layers hold state.** Check for the presence of each of the other three
       layers' state objects and abort naming the first one found. Destroying the state bucket while
       another layer's state lives in it orphans every resource that layer manages.
    3. **Migrate state back to local.** You cannot destroy the bucket your state lives in; this is
       the bootstrap chicken-and-egg in reverse and it is easy to forget.
    4. **Lift the destroy guard.** The guard only accepts a literal value — it cannot be driven by a
       variable, there is no override flag, and no tfvar can unlock it — so the only supported escape
       is editing the file. Do it with an in-place edit that writes a backup, and restore from that
       backup in a trap so an interrupted run cannot leave the guard down. Do NOT ship the two-block
       form the research illustrates: Terraform does not support splitting one resource across two
       blocks and it will not parse.
    5. **Empty the bucket, then destroy**, then remove the generated backend config and restore the
       guard.

    Add the target to `make help` with its description marked as a decommissioning operation, and
    confirm that no daily-loop target — none of the Phase 1 targets, and none of the Phase 2 targets
    that will arrive later — has any path that reaches the bootstrap layer.

    Do not execute this target. It is written, reviewed and left unexercised; verification is by

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request from any contributor -> AWS | A workflow file is code; a change to it is a change to what CI can do with the project's AWS credentials. |
| scheduled job -> the account | The sweep runs unattended, so its verdict is read by nobody at the time it is produced; an ambiguous verdict is silently useless. |
| operator keystroke -> the immortal layer | One target can destroy the Terraform state of every layer in the project. |
