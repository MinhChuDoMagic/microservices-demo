<objective>
Expand the proven sweep spine across the compute and storage orphan classes: EC2 instances,
snapshots, Elastic IPs and network interfaces, each with its false-positive exclusion proven against
a recorded fixture rather than against a live account.

Purpose: these four classes carry the exclusions that decide whether the sweep is trusted or
ignored. A terminated instance lingers in the API for about an hour after a *successful* teardown,
so reporting it breaks Phase 2's consecutive-clean-round-trips gate outright. Enumerating snapshots
without restricting to self-owned ones does not produce false positives — it hangs, then floods the
report. A detached endpoint or gateway interface is genuinely not the operator's to delete, and
reporting it sends them down a dead end. Each of these is cheap to get wrong and expensive to
discover on a live account at teardown time.

Output: five wired classes (the tracer's volumes plus four more), every exclusion pinned by a
two-sided fixture, and the exclusion suite green for all five.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AWS enumeration API -> sweep verdict | Each class's exclusion logic decides whether a real orphan is reported or a phantom is; both errors destroy the verdict's usefulness in opposite ways. |
| per-class failure -> overall verdict | A denied call for one class must not be absorbed into "that class found nothing". |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-18 | Spoofing | per-class exclusion logic | high | mitigate | Every exclusion is pinned by a two-sided fixture asserting both the reported and the excluded entry, so neither an over-broad nor an under-broad filter can pass. The call log assertion additionally proves the server-side restrictions were sent. |
| T-1-19 | Repudiation | per-class API failure | high | mitigate | Each check returns early on a wrapper failure and the failure lands in the errors array; the verdict block reads the hard-error accumulator first, so a partially-run sweep can never print a clean verdict. |
| T-1-20 | Denial of Service | snapshot enumeration | medium | mitigate | The self-owner restriction is applied on the API call with an inline comment marking it load-bearing, and asserted from the stub call log; without it the call enumerates every publicly shared snapshot and stalls. |
| T-1-21 | Tampering | report schema drift | medium | mitigate | The class-coverage guard fails the run when a schema class key has no registered check, so a later plan cannot add a key that silently reports empty forever. |
| T-1-SC | Tampering | package-manager installs | low | accept | No npm, pip or cargo install occurs in this plan; the sweep is Bash plus the AWS CLI and jq, both already present and asserted by `make doctor`. |
</threat_model>
