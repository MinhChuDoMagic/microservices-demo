<objective>
Build the Wave 0 validation harness that `01-VALIDATION.md` makes binding: `bats-core` plus a
stubbed `aws` binary that replays recorded JSON, plus the four assertion suites. Nothing in this
plan implements sweep logic.

Purpose: LIFE-05's genuinely hard part is not enumerating resource classes — it is the
*false-positive exclusions*. A pristine AWS account contains one undeletable `default` security
group per VPC per region, a dozen undeletable service-linked IAM roles, and terminated EC2 instances
that linger for about an hour after a successful teardown. A sweep that reports those is worse than
no sweep, and every one of those exclusions is expensive to prove against a live account and cheap
to prove against a fixture. Writing the sweep first and testing it later inverts the phase's premise.

Output: `bats tests/` exits 0 today (suites targeting not-yet-written code skip with a named reason)
and becomes the red-to-green driver for plans 01-04, 01-05, 01-07 and 01-08.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process -> PATH | The harness deliberately places an executable named `aws` ahead of the real CLI; if that shim outlives the test it silently intercepts real operator commands. |
| fixture file -> assertion | A one-sided fixture (only must-exclude entries, or only must-report entries) turns a suite into a rubber stamp. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-05 | Tampering | `tests/helpers/stub-aws.bash` PATH shim | medium | mitigate | The shim lives in a `mktemp -d` directory removed by `stub_aws_stop` and by a bats teardown trap; it is never written into the repository and never into a persistent bin directory. The self-test asserts PATH is restored. |
| T-1-06 | Spoofing | fixture-driven assertions | high | mitigate | The two-sided-oracle rule is enforced by task 2's acceptance criteria and by a row-count assertion against `tests/fixtures/aws/README.md`, so a fixture cannot be added without declaring both sides. |
| T-1-07 | Repudiation | permanently skipped suites | high | mitigate | Skip reasons are constrained to a plan-attributed `MISSING — created in 01-0N` sentinel and asserted by this plan; plan 01-09 asserts zero skips remain before the phase closes. |
| T-1-SC | Tampering | `bats-core` / `shellcheck` installation | low | accept | Installed from the operator's system package manager; no npm/pip/cargo manifest enters the repository and no package-manager lockfile is added, so no supply-chain artifact is introduced into version control. |
</threat_model>
