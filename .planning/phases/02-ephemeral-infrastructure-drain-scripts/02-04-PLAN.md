## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator workstation → EKS API | Credentials, endpoint CIDR, and kubeconfig determine whether Kubernetes deletions can run. |
| Kubernetes controllers → ELBv2/EC2/EBS | Controller cleanup is asynchronous and is confirmed through separate AWS APIs. |
| AWS CLI JSON → drain decision | API errors and unknown states must not be interpreted as absence. |

ASVS L1 is applied; any high-severity threat blocks plan completion.

## Assumptions

- [GATED] CREATING/FAILED states pass only when each relevant AWS query successfully proves absence/terminal state. Residual ALB/target-group, Karpenter instance, or PVC-volume IDs block teardown and require type-specific operator remediation; this invocation does not auto-clean those resources.
- [GATED] DEGRADED states and API-unreachable ACTIVE/DEGRADED paths fail closed if Kubernetes draining is impossible and any AWS resource remains. Preserve the originating API error, report stage/state/type/IDs/elapsed time, restore API access or explicitly handle the listed resource, then rerun `make down` from step one.
- [GATED] `make nuke-project` is a separate option only for resource types proven safe under its fixed positive Project-tag filter. Untagged and unproven resources stay report-only for explicit operator handling; a fresh teardown run advances only after AWS confirms every relevant set absent/terminal.
