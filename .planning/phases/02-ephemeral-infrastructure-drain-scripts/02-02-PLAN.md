## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator workstation → EKS public endpoint | A trusted operator CIDR and AWS access entry grant Kubernetes API reachability. |
| Terraform configuration → AWS APIs | HCL creates tagged networking, IAM, and EKS resources in the selected account. |
| EKS module → managed add-on APIs | Module inputs select cluster and add-on versions. |

ASVS L1 is applied; any high-severity threat blocks plan completion.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | E — Elevation of Privilege | EKS API endpoint/access entry | high | mitigate | Require a validated operator CIDR and explicit access entry; reject world-open CIDR in tests and preflight. |
| T-02-06 | T — Tampering | Module/provider/add-on resolution | high | mitigate | Exact registry/module/add-on pins, committed lockfile refresh through Make validation, and matching VERSIONS.md contracts. |
| T-02-07 | I — Information Disclosure | AWS tags and operator endpoint | medium | mitigate | Use project default tags and restrict the endpoint to the operator CIDR; no credentials or account IDs enter tracked inputs. |
| T-02-08 | D — Denial of Service | Failed provisioning | medium | mitigate | One apply attempt, preserve partial state and diagnostics, and no automatic rollback/retry. |
</threat_model>
