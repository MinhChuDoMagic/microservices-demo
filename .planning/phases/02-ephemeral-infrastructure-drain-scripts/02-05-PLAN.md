<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AWS response fixture → stub | Test data stands in for untrusted AWS API bodies and error channels. |
| Stubbed AWS API → drain state machine | Call count and response sequence determine whether teardown may progress. |
| Drain test → destroy command | A false-positive terminal state could trigger irreversible Terraform deletion. |

ASVS L1 is applied; any high-severity threat blocks plan completion.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-17 | T — Tampering | Fixture response selection | high | mitigate | Scenario mode is opt-in, operation-keyed, call-counted, and fails on missing response; harness self-tests cover precedence. |
| T-02-18 | D — Denial of Service | Retry behavior | medium | mitigate | Tests prove fixed retry counts and that failures consume the one shared deadline. |
| T-02-19 | R — Repudiation | Drain state assertions | medium | mitigate | Assert AWS argv, response transitions, output diagnostics, and absence of destroy in the call log. |
| T-02-20 | E — Elevation of Privilege | False clean state | high | mitigate | Unknown/malformed/error responses are explicitly negative cases and never satisfy absence predicates. |
</threat_model>
